Excel + VBA

Coffee Sales Dashboard

An interactive Excel dashboard built from 1,000 coffee order records covering January 2019 to August 2022. The dataset includes customer, product, coffee type, roast type, size, country, quantity, pricing, and sales information. Slicers and a timeline filter every chart at once, and a VBA macro audits the raw data for quality issues.

Process

How I built it

01 · Combine

Join the tables

Pulled customer details and product details from separate sheets into each order row with XLOOKUP, and calculated sales per line (unit price × quantity).

02 · Analyze

Summarize with pivots

Built pivot tables for sales over time, by country, by coffee type, roast and size, and for the top five customers.

03 · Visualize

Build the dashboard

Turned the pivots into charts on one dashboard sheet, then connected slicers and a timeline so every chart filters together.

04 · Validate

Audit with a macro

Wrote a VBA macro that checks every order row for missing, duplicate and invalid values and logs each problem to an Exceptions sheet.

Data quality

Auditing the data with a VBA macro

Before trusting the dashboard, I wrote a macro (CheckDataQuality) that reads every row of the orders sheet, runs five checks, and writes each problem — row number, Order ID and reason — to a new Exceptions sheet. It finds columns by their header names, so it keeps working if the column order changes.

What the results mean: the 207 issues sit on 200 different orders. Missing emails don't change any sales figures, but they matter for customer follow-up and loyalty marketing. Quantities and dates were all clean, so the totals on the dashboard rest on valid numbers.
The duplicate: order NOP-21394-646 lists the same product (L-D-2.5) on two lines, with quantities of 2 and 3. That's likely one purchase of 5 split in two — worth merging so per-product line counts aren't inflated.
Also noted: the workbook has 1,000 order rows but 957 unique Order IDs, because some orders contain more than one product. Each row is a line item, so totals are summed across line items. Customer names and contact details are sample data, not real people.
